# Invite-Only Registration — Design Spec

**Date:** 2026-05-31
**Status:** Approved
**Source:** `docs/invite-registration-plan.html`

## 1. Goal

Close open registration. All new accounts must provide a one-time-use 6-digit registration code generated by an admin. The guest login endpoint stops creating accounts.

## 2. Database

### New table: `registration_codes`

```sql
CREATE TABLE registration_codes (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    code            VARCHAR(6) NOT NULL UNIQUE,
    is_used         BOOLEAN DEFAULT FALSE,
    is_disabled     BOOLEAN DEFAULT FALSE,
    used_by_user_id BIGINT NULL,
    used_at         DATETIME NULL,
    created_by      BIGINT NOT NULL,
    note            VARCHAR(255) DEFAULT '',
    created_at      DATETIME DEFAULT NOW(),
    updated_at      DATETIME DEFAULT NOW(),
    INDEX idx_code (code)
);
```

### Code generation rules

- 6-digit numeric string (`000000`–`999999`), zero-padded
- Generated server-side with `crypto/rand`
- Retry on unique constraint collision (rare at this scale)
- No expiration — codes are valid until used or disabled

## 3. Backend Changes

### 3.1 Modified: `POST /api/auth/register`

**New request body:**
```json
{
  "nickname": "string",
  "password": "string",
  "registration_code": "string (6 digits)"
}
```

**Behavior:**
- Missing `registration_code` → `400 { "error": "registration_code_required" }`
- Code not found → `403 { "error": "invalid_registration_code" }`
- Code already used → `403 { "error": "registration_code_already_used" }`
- Code disabled → `403 { "error": "registration_code_disabled" }`
- Valid code → proceed with user creation, mark code used in same transaction
- Nickname duplicate → `409` (unchanged)

### 3.2 Modified: `POST /api/auth/guest`

Always returns `403 { "error": "guest_registration_closed" }`. No account creation. Route path preserved for compatibility.

### 3.3 New admin endpoints

All behind `Auth` + `AdminOnly` middleware at `/api/admin/registration-codes`.

| Method | Path | Input | Output |
|--------|------|-------|--------|
| `GET` | `/api/admin/registration-codes` | `?page=&size=` | Paginated list with used_by nickname |
| `POST` | `/api/admin/registration-codes` | `{ "count": int, "note": "string" }` | Created codes array |
| `PUT` | `/api/admin/registration-codes/{id}/disable` | path param | Success/error |

**POST generate:** count range 1–100. Returns the full code objects so admin can copy them.

**PUT disable:** Only works on unused, non-disabled codes. Returns error if already used.

## 4. Frontend Changes

### 4.1 Modified: Register page (`frontend/app/auth/register/page.tsx`)

- Add "注册码" input field (6-digit numeric, required)
- Phone keyboard hint: `inputMode="numeric"`, `maxLength={6}`
- Error states: invalid code, already used, code disabled — display inline error message
- Form layout: nickname → password → registration code → submit button

### 4.2 Modified: apiClient (`frontend/lib/api-client.ts`)

`register()` signature becomes:
```typescript
async register(nickname: string, password: string, registrationCode: string)
```
Request body includes `registration_code` field.

### 4.3 New: Admin registration codes page (`frontend/app/admin/registration-codes/page.tsx`)

**Layout:**
- Header: "邀请码管理" title + "生成邀请码" button
- Stats row: 3 cards — total codes / used / unused
- Table: code, status badge, note, used by (nickname), created at, used at, actions
- Pagination (same pattern as users page)

**Generate dialog (modal):**
- Count input (default 1, max 100)
- Optional note field
- On submit: calls POST, shows generated codes with copy-to-clipboard buttons

**Table actions:**
- Copy code to clipboard
- Disable (unused codes only), with confirmation

**Status badges:**
- 🟢 未使用 (Unused)
- 🔵 已使用 (Used) — shows user nickname
- 🔴 已禁用 (Disabled)

### 4.4 Modified: Admin sidebar (`frontend/components/ui/AdminSidebar.tsx`)

Add nav item: `🔑 邀请码` → `/admin/registration-codes`

### 4.5 Admin API functions

Add to `frontend/lib/admin-fetch.ts` or create `frontend/lib/admin-api.ts`:
- `fetchRegistrationCodes(page, size)`
- `generateRegistrationCodes(count, note)`
- `disableRegistrationCode(id)`

## 5. Test Plan

### Backend tests (`server/internal/api/` and `server/internal/model/`)

| Test | Coverage |
|------|----------|
| Register without code | 400, "registration_code_required" |
| Register with invalid code | 403, "invalid_registration_code" |
| Register with already-used code | 403, "registration_code_already_used" |
| Register with disabled code | 403, "registration_code_disabled" |
| Register with valid code | 200, token+user returned, code marked used |
| Concurrent same-code registration | Only one succeeds |
| Guest login | Always 403, no user created |
| Admin generate codes | Returns correct count, codes are unique 6-digit |
| Admin list codes | Paginated, includes used_by nickname |
| Admin disable code | Works on unused, fails on already-used |
| Non-admin access | 401/403 for all registration-code endpoints |

### Frontend checks

- `apiClient.register()` sends `registration_code` in request body
- Register page renders 3 fields, numeric keyboard on mobile
- Admin page loads, generates, copies, and disables codes
- `npx tsc --noEmit` and `npm run lint` pass

## 6. Implementation Order

1. Database migration + model/store
2. Backend auth changes (register + guest)
3. Backend admin endpoints
4. Backend tests
5. Frontend apiClient + register page
6. Frontend admin page + sidebar
7. Full verification (go vet + go test + tsc + lint)

## 7. Out of Scope

- Code expiration dates
- Multi-use codes
- Self-service code request page
- Changing existing login flow
